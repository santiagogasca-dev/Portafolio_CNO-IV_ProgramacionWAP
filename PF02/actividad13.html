Pentesting y Red Team — My File Server: 1

Evaluación de seguridad ofensiva sobre una infraestructura virtualizada, desde el reconocimiento inicial hasta la obtención de privilegios de root.

Estudiante
Santiago Isaac Gasca López
Parcial
I · Fundamentos de Ciberseguridad
Tema
Pentesting · Red Team
Producto
Reporte Técnico · Auditoría

01 · Executive Summary

Durante el mes de septiembre de 2026 se realizó una evaluación de seguridad ofensiva, bajo la modalidad Red Team, sobre la infraestructura virtualizada My File Server: 1.

El objetivo fue identificar vulnerabilidades que pudieran afectar la confidencialidad, integridad y disponibilidad de los activos informáticos de la organización.

Como resultado de la evaluación se logró comprometer el sistema hasta obtener acceso como root. El acceso inicial se consiguió a partir de la enumeración de los servicios expuestos y posteriormente se aprovechó una vulnerabilidad del kernel identificada como CVE-2016-5195 (DirtyCow).

A partir de los resultados obtenidos se recomienda realizar un plan de parcheo y endurecimiento de los servicios involucrados.

02 · Alcance (Scope)

  • Objetivo evaluado: Servidor de archivos corporativo simulado My File Server: 1, con IP asignada dentro del entorno de pruebas controlado.
  • Tipo de prueba: Caja negra simulada a caja gris (Gray-Box / Black-Box).
  • Vectores analizados: Servicios de red expuestos como FTP, SSH, HTTP y SMB, configuraciones de control de acceso y estabilidad del kernel del sistema operativo.

03 · Metodología Aplicada

La evaluación se realizó tomando como referencia los estándares de pruebas de penetración PTES (Penetration Testing Execution Standard) y las directrices de OWASP.

El trabajo se dividió en cinco fases:

  1. Reconocimiento y Descubrimiento: identificación de equipos activos y direccionamiento IP dentro de la red.
  2. Enumeración: análisis de puertos abiertos, versiones de software y servicios expuestos.
  3. Análisis de Vulnerabilidades: identificación de configuraciones inseguras y software desactualizado.
  4. Explotación: ejecución controlada de técnicas para obtener el acceso inicial.
  5. Post-Explotación y Escalada: elevación de privilegios para demostrar el impacto alcanzable sobre el sistema.

04 · Fases de Reconocimiento

Mediante herramientas de descubrimiento de red como netdiscover, se ubicó la dirección IP del servidor objetivo dentro del segmento de red aislado.

Con esto se confirmó que el objetivo se encontraba operativo y que utilizaba una arquitectura basada en CentOS 7.

05 · Enumeración

Se realizaron escaneos avanzados utilizando Nmap con la opción -A, con el objetivo de obtener información sobre los puertos abiertos, servicios y versiones detectadas.

Los principales servicios encontrados fueron:

  • 21/TCP — FTP: Servicio vsftpd 3.0.2.
  • 22/TCP — SSH: Servicio OpenSSH 7.4.
  • 80/TCP — HTTP: Servidor Apache/2.4.6 (CentOS) albergando el sitio principal.
  • 445/TCP — SMB: Servicio Samba smbd 4.9.1 con recursos compartidos accesibles.
  • 2121/TCP — FTP Secundario: ProFTPD 1.3.5 con soporte de acceso anónimo.
nmap -A <IP-del-objetivo>

06 · Explotación

Acceso inicial

Durante la enumeración del servidor web, utilizando nikto, se localizó el archivo expuesto /readme.txt.

El archivo contenía credenciales preliminares y pistas relacionadas con el entorno.

Inyección de llaves

Aprovechando los permisos de escritura disponibles mediante el servicio FTP sobre la cuenta del usuario smbuser, se generó un par de llaves SSH desde la máquina atacante.

Posteriormente, la llave pública fue colocada en el archivo authorized_keys dentro del directorio remoto:

/home/smbuser/.ssh/

Esto permitió establecer una sesión interactiva mediante SSH sin necesidad de utilizar una contraseña.

07 · Escalada de Privilegios

Una vez dentro del sistema como usuario estándar smbuser, se evaluó la versión del kernel mediante el comando:

uname -a

El resultado reveló la ejecución de:

Linux 3.10.0-229.el7.x86_64

Se identificó que esta versión es vulnerable a la condición de carrera del kernel conocida como DirtyCow (CVE-2016-5195).

Se transfirió el código fuente del exploit 40616.c mediante un servidor HTTP local en Python.

Después se compiló el código en la máquina víctima utilizando gcc y se ejecutó el archivo generado:

./upslp

La explotación se realizó con éxito, logrando sobrescribir los permisos de escritura y obteniendo una shell interactiva con privilegios de root.

08 · Análisis de Impacto (Modelo CIA)

Confidencialidad — Crítico

La obtención de privilegios de root permite acceder a los archivos del sistema, bases de datos y credenciales de usuario.

Integridad — Crítico

Un atacante externo puede modificar archivos críticos del sistema operativo, introducir software malicioso y alterar configuraciones de red.

Disponibilidad — Alto

Existe riesgo de provocar una denegación de servicio mediante la caída intencional de los servicios de archivos y web expuestos.

09 · Recomendaciones Técnicas

  1. Parchado del Kernel: actualizar de forma inmediata el sistema operativo CentOS a versiones de kernel más recientes que mitiguen la vulnerabilidad CVE-2016-5195.
  2. Eliminación de archivos sensibles: remover archivos informativos temporales o de prueba, como readme.txt, cuando estén expuestos en el servidor web.
  3. Endurecimiento de servicios (Hardening): deshabilitar el acceso anónimo en los servidores FTP y restringir los permisos de escritura en los recursos compartidos de SMB.
