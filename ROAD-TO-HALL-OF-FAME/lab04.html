File Path Traversal: Traversal Sequences Stripped with Superfluous URL-Decode

Laboratorio de PortSwigger Web Security Academy enfocado en el bypass de filtros de Path Traversal mediante una decodificación URL superflua.

02 · OBJETIVO

Objetivo

Demostrar y documentar la explotación de una vulnerabilidad de File Path Traversal utilizando una técnica de bypass basada en codificación URL superflua.

El objetivo es manipular una petición HTTP mediante Burp Suite para conseguir que la aplicación procese una secuencia de traversal después de que el filtro inicial ya haya realizado su validación.

03 · MARCO TEÓRICO

Marco Teórico

El ataque de File Path Traversal ocurre cuando una aplicación utiliza información proporcionada por el usuario para construir una ruta de archivo sin aplicar una validación adecuada.

Una técnica común consiste en utilizar secuencias como ../ para desplazarse fuera del directorio esperado.

Las aplicaciones pueden intentar bloquear estas secuencias mediante filtros que eliminan patrones considerados peligrosos.

Sin embargo, cuando la aplicación realiza una decodificación URL adicional o superflua después de aplicar el filtro, una secuencia que inicialmente parecía segura puede convertirse posteriormente en una secuencia válida de traversal.

En este laboratorio se aprovecha precisamente este comportamiento mediante una doble codificación URL.

04 · VULNERABILIDAD IDENTIFICADA

Vulnerabilidad identificada

La vulnerabilidad corresponde a File Path Traversal: Traversal Sequences Stripped with Superfluous URL-Decode.

El problema se produce porque el filtro elimina o bloquea las secuencias de traversal durante una primera etapa, pero posteriormente la aplicación vuelve a decodificar el valor recibido.

De esta manera, una secuencia codificada puede transformarse nuevamente en:

../
05 · PROCEDIMIENTO

Procedimiento paso a paso

Paso 1. Interceptar la petición

Se utiliza Burp Suite Proxy para interceptar las solicitudes realizadas por la aplicación.

Paso 2. Identificar el parámetro vulnerable

Se identifica la solicitud encargada de cargar una imagen mediante el parámetro filename.

Paso 3. Identificar la petición original

La solicitud normal contiene un nombre de archivo, por ejemplo:

GET /image?filename=X.jpg HTTP/1.1

Paso 4. Enviar la petición a Repeater

La solicitud interceptada se envía a Burp Repeater para modificar el parámetro filename.

Paso 5. Aplicar la doble codificación

Se sustituye el valor original por una secuencia doblemente codificada que permita evadir el filtro.

Paso 6. Enviar la petición

Finalmente se envía la solicitud modificada y se observa la respuesta del servidor.

06 · PETICIÓN BASE

Petición HTTP original

La solicitud inicial utiliza el parámetro filename para cargar una imagen: 

GET /image?filename=X.jpg HTTP/1.1

Esta petición sirve como punto de partida para modificar el valor utilizado por la aplicación.

07 · PAYLOAD

Payload utilizado

Para realizar el bypass se utiliza la siguiente petición: 

GET /image?filename=..%252f..%252f..%252fetc/passwd HTTP/1.1

El payload utiliza una representación doblemente codificada de la barra / utilizada en la secuencia de traversal.

08 · EXPLICACIÓN TÉCNICA

Explicación técnica

La cadena ..%252f contiene una codificación adicional.

El valor %25 representa el carácter %. Por lo tanto, después de una primera decodificación, la secuencia puede convertirse en:

..%2f

Posteriormente, cuando la aplicación realiza una segunda decodificación URL, el valor puede transformarse en:

../

De esta forma, el filtro inicial no detecta directamente la secuencia de traversal, pero la aplicación termina procesándola después de la segunda decodificación.

09 · RESULTADO ESPERADO

Resultado de la explotación

Si el bypass se procesa correctamente, la aplicación interpreta la secuencia de traversal y puede acceder al archivo:

/etc/passwd

10 · IMPACTO

Impacto

Una vulnerabilidad de File Path Traversal puede permitir que un atacante acceda a archivos que deberían permanecer fuera del alcance de la aplicación.

En este laboratorio se demuestra el acceso al archivo /etc/passwd, lo que evidencia una afectación a la confidencialidad de la información.

La gravedad real dependerá de los permisos del proceso que ejecuta la aplicación y de los archivos accesibles dentro del sistema.

11 · MITIGACIÓN

Medidas de mitigación

Para prevenir este tipo de vulnerabilidades se deben evitar procesos de decodificación innecesarios o múltiples sobre una entrada controlada por el usuario.

También se recomienda realizar una correcta normalización y canonicalización de las rutas antes de utilizarlas.

Las validaciones deben realizarse sobre la ruta final que realmente será utilizada por el sistema de archivos, no solamente sobre una representación intermedia de la entrada.

Siempre que sea posible, la aplicación debe utilizar identificadores controlados internamente en lugar de permitir que el usuario determine directamente una ruta de archivo.

13 · CONCLUSIÓN

Conclusión

En esta actividad se demostró cómo una validación insuficiente de las rutas puede ser evadida mediante una codificación URL superflua.

El laboratorio permitió comprender la importancia de realizar correctamente los procesos de decodificación, normalización y validación antes de utilizar una entrada proporcionada por el usuario para acceder a archivos.

La práctica también permitió observar que bloquear directamente determinadas cadenas no garantiza que una aplicación sea segura cuando existen diferentes etapas de transformación de la entrada.
